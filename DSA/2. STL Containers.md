1. Pair (pair<dtype>)
2. Vector (vector<dtype>): Provides random access, fast insertions and deletions at the end, but linear time complexity for operations at middle of container
	1. Subarray is non-empty contiguous
	2. Subsequence can be empty, and in same sequence but not necessarily contiguous
3. Deque (deque<dtype>): Similar to vector, but also provides fast insertions at beginning
	1. push_back
	2. push_front
	3. erase
	4. empty: check if empty
	5. front
	6. back
	7. pop_front
	8. pop_back
4. List (list<dtype>): Maintains doubly linked list, all insertions and deletions take constant time, but does NOT provide contiguous and random access, ie: iterating takes linear time.
	1. Reverse
	2. Sort
	3. insert(iterator, element) will insert element at iterator's location
	4. remove(element) will remove all occurrences from list
	5. merge(): Merges two sorted lists into one.
	6. Everything else in deque
5. Stack (stack<dtype>): LIFO, all operations O(1). top() returns element, pop() removes it.
6. Queue (queue<dtype>): FIFO, similar to stack
	1. push(element)
	2. pop()
	3. front() and back()
	4. empty() and size()
7. Priority queue (priority_queue<dtype>): Also called max_heap, similar to queue, except it maintains a tree, and returns larger element first. Push and pop take O(log(n)), and top() takes O(1). Does not provide indexing.
8. Reverse priority queue (priority_queue<dtype, vector<dtype>, greater<dtype>>: Also called min_heap, opposite of priority queue.
9. Set (set<dtype>): Stores unique values in sorted fashion. set.insert() is used instead of push(). Does not support indexing. Non linear container like priority queue, and tree is maintained.
	1. insert()
	2. find() returns iterator. *(iterator) will give value. If not found, returns set.end() iterator
	3. erase() can take either iterator or value. erase(iterator) or erase(element). Also can take 2 args: [start iterator, end iterator).
	4. count() gives 1 if element found, else gives 0.
	5. insert(), find() take log(N) time
	6. erase() can take O(1) amortized time if an iterator is provided, if value is provided, find() needs to be run in background which gives O(log(N)) time complexity. – verify again to be sure.
	7. Also has lower_bound() and upper_bound()
10. Multiset (multiset<dtype>): Same as set except for the following differences:
	1. Can have multiple copies of same element
	2. If erase called with element, will remove all occurrences of element
	3. If erase called with iterator, or range of iterators, only those occurrences will be erased.
	4. find() will return iterator to first occurrence of element.\
11. Unordered Set (unordered_set<dtype>): Similar to set, except unordered, because of which, time complexity is constant, ie: O(1) amortized, O(N) in the worst case.
12. Map (map<dtype, dtype>): Can be indexed, sorted in order of keys, unique keys only. Can add elements in following ways:
	1. mp[1] = 2
	2. mp.insert({1, 2})
	3. mp.emplace({1, 2})
	4. mp.erase(el)
	5. Can get iterator to first occurrence with find()
	6. Can be used like mp[5] -> returns value at key 5; If key does not exist, it might return 0, and should be used like if (mp.find(5) != mp.end()) do something.
13. Multimap (multimap<dtype,dtype>): Similar to set and multiset
14. unordered_map<dtype,dtype>: same as set and unordered_set
